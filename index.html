Reading what the categories hide — a live 311 demonstration

Most performance data dies as something you collect. This shows the step that makes it something you can act on: reading the free-text a resident actually wrote, which the category field throws away — and doing it three ways, including with no account and no internet at all.

▶ Launch the demo How to run it View the code

· What it does

It takes a month of real 311 service requests — pulled from the public Open311 feed for New Haven, Connecticut — and compares two views. The first is the dashboard everyone already has: a bar chart of the category each request was filed under. The second is what the words say. Reading the descriptions surfaces things the categories bury: seven requests logged as routine "Parking Violations" turn out to be one repeated problem — fraudulent police placards used to park at a single downtown block over three weeks — plus a handful of genuine safety items (exposed wiring filed under "Parks," a trip-and-fall, a dead pedestrian signal) that their category labels gave no urgency to. None of it needed new data. The signal was already in the system, just miscategorized in a way that let it age.

· Three ways to run it

Same demo, same data — you choose how the reading in move 02 happens.

In your browser runs here · nothing to install

The default engine is transparent keyword logic that runs entirely in the page — no account, no key, no internet. It shows the exact rule that fired for each record, so nothing is hidden. This is the version hosted on this site.

  1. Click Launch the demo.
  2. Press Run classification, then Draft the council brief.

With your own open model download & run locally

Point the demo at an open-weight model you run yourself — LM Studio or Ollama — to watch a real LLM do the reading, fully on-prem. No resident data leaves your machine.

  1. Start your model server (LM Studio on :1234, or Ollama on :11434) and enable its CORS option.
  2. Download demo.html and open it from your own computer (double-click, i.e. file://).
  3. Switch the engine toggle to Local open model, confirm the endpoint, and run.
Why download? This site is served over https, and browsers block an https page from calling http://localhost. Running the file locally removes that restriction.

Inside Claude.ai managed model · no key

A second build (claude-version.html) runs the reading on Anthropic's hosted model with no API key — but only inside a Claude.ai session, where that call is handled for you. Hosted here it will display but won't classify.

  1. Open a chat at claude.ai and paste the contents of claude-version.html as an artifact.
  2. Run it there; the buttons call the model live.

· Method & honest caveats

Real data. The records are a live public Open311 pull. To point the demo at another city, swap the RECORDS array near the top of the file and map service_name → intake, description → text. Many small cities have dormant feeds — a useful finding in itself.

Verify before you cite. A hosted model in an early draft confidently named the wrong city's police department because it saw "Wall Street." The analysis was right; a proper noun was invented. That is the governance lesson baked into this demo: AI-drafted narrative is a first draft to check, never a citation. Every agency, statute, or figure gets traced to source by a human before it reaches a council packet.

Aggregate only. This understands patterns; it decides no individual case. In production, scrub personal information before any model reads the text.
